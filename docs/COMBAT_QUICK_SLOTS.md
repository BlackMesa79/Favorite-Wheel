# 战斗预设 1–8 快捷槽

2026-10-13，纳入 0.7.0。用户选择使用原版 1–8 槽位，并处理与物品的冲突，已确认战斗预设快捷键分配和鼠标左右手切换测试通过。

## 使用

1. 打开功能轮盘，切换到战斗预设。
2. 悬浮一个已保存的预设，按 1–8 分配槽位；再按当前相同数字解除绑定。每个预设最多占一个槽，每个槽最多分配一个预设。
3. 扇区内沿显示槽位号码，轮盘底部显示悬浮绑定提示。长名称在可能靠近数字的位置收窄显示，详情卡仍显示完整名称。
4. 关闭轮盘后，在正常游戏中按相应的原版快捷键应用该预设。重复应用已装备的预设会保持装备。缺失或改变的装备按现有预检提示，不先卸下当前装备。
5. 编辑后保存游戏；绑定属于当前角色的 `.skse` 存档，主 INI 不保存这些槽位。旧存档不会自动分配槽位。

数字按键对应现有 `QuickSlotFromKey`：识别原版 Hotkey1–Hotkey8 事件与物理数字 1–8，保留现有重映射识别。Ctrl/Shift/Alt + 数字不应用战斗预设；9/0 和扩展槽不拦截。菜单、设置、命名对话框、轮盘打开/关闭过渡、读档、焦点丢失和装备任务处理中不启动新预设。轮盘入口绑定仍有优先权；如果入口占用了同一数字，应先改变入口绑定。

## 槽位冲突

- 分配给战斗预设：解除该槽位的原版物品/法术/吼声绑定和原战斗预设绑定。物品仍保持收藏，其他槽位及扩展槽不变。
- 在轮盘内分配回收藏物品：只有物品绑定成功后，才解除该槽的战斗预设绑定。失败不会丢掉已有战斗槽。
- 后来在 SkyUI/原版菜单中重新绑定物品：下次游戏内按该槽时，原版绑定优先；原输入事件继续传给游戏，并安排解除旧的预设绑定。不会同时应用预设和物品。
- 解除、删除或移动预设的槽位不会自动恢复之前被替换的物品绑定；需要时重新分配物品。
- 覆盖预设装备、重命名会保留槽位；删除预设则释放其绑定。

原版槽冲突只在真正按下且存在战斗槽时检查，不在每帧扫描库存。物品与预设的绑定修改、应用都走游戏任务队列；按键与生命周期检查防止读档后执行旧任务。应用沿用已有的装备预检和逐步验证，不绕过装备逻辑。

## 存档兼容

原战斗装备记录 `FWCP` / `FWC 1` 保持原格式，新增独立 `FWCK` / `FWQ 1` 绑定记录。绑定记录与装备记录的读取顺序均可处理；旧 0.6.2 存档没有绑定记录时使用未绑定状态。旧 DLL 仍能读取战斗装备记录，回滚后保存会丢掉它不认识的新快捷槽记录。

绑定记录限制 8 个槽位和 1024 字节，拒绝无效/重复槽、重复 ID、未知版本和尾随数据。损坏的绑定记录不阻止读取战斗装备；找不到的预设 ID 不生成虚假预设。切换角色/新游戏会清理待恢复绑定。

## 验证

16 项本地套件通过。CombatPresetTests 覆盖绑定、转移、解除、无效 ID/槽、独立记录往返、旧 FWC1、不同读取顺序、损坏绑定及场景限制。WheelLogicTests 使用实际 InputGate 和 InputDispatchChain 确认：只有战斗槽的按下/保持/释放被捕获，原版槽与新物品冲突事件正常传递。RuntimeLayoutTests 保留对原版 ExtraHotkey 字节与收藏标记的检查。

英文 Skyrim 1080p 和中文 Classic 720p 原生离屏检查通过：槽号、图标、名称、详情和底部绑定提示没有重叠。日志和预览为 `build/post062-*`、`build/hands-skyrim-combat-hotkeys-1920.jpg`、`build/hands-classic-combat-hotkeys-1280.jpg`。

用户已确认自己的本地游戏测试通过，未提供逐项运行时矩阵。以下保留为完整复测清单：物品槽→战斗槽→其他战斗槽→物品槽；重复同数字解除；覆盖/重命名保留槽位；删除释放；保存退出后读档；SkyUI 后绑定的物品优先；缺失武器/法术、菜单与快速连续按键。本功能已纳入 0.7.0 正式材料，原 0.6.2 安装包与源码包保留。见 [发布记录](RELEASE_0.7.0.md)。
