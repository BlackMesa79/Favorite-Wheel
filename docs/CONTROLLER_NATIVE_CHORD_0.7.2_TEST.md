# 0.7.2 自定义手柄组合键兼容测试

2026-10-18 更新：反馈者确认此独立补丁已修复问题，已合入 0.7.3 正式修复版。升级后停用独立 controller-chord 测试补丁，避免它覆盖正式 DLL。下面保留调查和测试时的记录。

## 反馈证据

反馈者的映射截图为 `Favorites = All Of (360_LB, 360_Y)`。提供的 0.7.2 日志来自 1.6.1170；15 次手柄入口均为 Y，`nativeRequired=0100`（LB），但事件跟踪仅有 `heldMask=2000`（Y），因此 `mode=none`。例如 21:00:35.252：LB 的零值释放事件与 Y 的入口同一时刻出现；21:00:35.394，LB 又恢复为按住，持续时间从 0.3508 秒延续为 0.3675 秒。后续多次重复这个序列。

这符合组合键处理临时屏蔽修饰键事件的特征。日志能证明轮盘在入口判断时缺少 LB，不能单独证明由 Kontrol、Gamepad++、其他组件还是游戏内部的哪一处产生该事件。旧日志没有设备当前 XInput 包或 `userEvent` 标签，需要补丁日志进一步确认。

轮盘设为「使用游戏设置」时继续继承游戏映射中的 LB，所以关闭轮盘自己的额外修饰键仍无法绕过这个检查。不能用移除原生 LB 要求来修复，否则可能吞掉单按 Y 的 Jump。

## 测试修复

保留跨输入包的事件跟踪，用于稀疏输入、自定义／模拟事件和真实释放。每个输入回调额外读取一次游戏当前的原生 XInput 包，用于补足被临时屏蔽的入口修饰键：

- 必须是连接且启用的设备，并通过 Skyrim RTTI 确认为 `BSWin32GamepadDevice`，才读取对应的 CommonLib 当前状态访问器。其他设备提供者继续使用事件路径。
- 当前包必须包含同一个主键，才可以补足配置／原生绑定要求的修饰键。无关按钮、上一次输入包和按键时长不参与补足。
- 不修改持久事件跟踪，不增加松开宽限期；真实松开 LB 且当前包中也没有 LB 时，单按 Y 仍交回游戏。
- Favorites 与 Actions 的原有优先级、阻塞菜单、上下文控制组、轮盘关闭流程和按下／按住／释放所有权保持原有规则。
- 诊断新增 `engineAvailable`、`engineMask`、`openingMask`、`event`，入口和加载标识为 `events+engine-v2`。修饰键转换日志仍记录原始事件。

这是受影响环境的试验补丁：如果设备当前包也已经被过滤，或不是该原生设备类型，可能仍无法补足 LB；新增日志用于区分这些情况。没有把事件标签 `Favorites` 本身当成无条件绕过组合键的依据。

## 独立构建与测试

独立补丁从已验证 SHA256 的正式 0.7.2 源码包提取，运行时修改仅在 `include/InputBindings.h`、`src/Wheel.cpp`；回归检查在 `tests/WheelLogicTests.cpp`、`tests/RuntimeLayoutTests.cpp`。不包含战斗循环开发功能。正式发布归档与现有本地安装保持原样。

逻辑检查重现「LB 按住 → LB 释放与 Y 按下同包 → LB 恢复」，验证修复后的入口、实际松开、当前包不可用、当前包没有主键、无关按钮、独立 Actions 修饰键及按键释放后的下次 Jump。运行时布局检查区分当前／上一 XInput 包，并检查 RTTI／动态转换所需的真实 Address Library ID。

实际设备效果仍需反馈者验证，不能用纯逻辑测试代替游戏测试。让他保持原来的 LB+Y 映射，安装 DLL 补丁并重启游戏，测试单按 Y、LB+Y、键盘收藏键，以及松开 LB 后再次单按 Y。若失败，请提供本次完整日志，重点是新版 `Controller entrance` 记录。
