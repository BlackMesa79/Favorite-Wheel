# 0.4.6 装备预设“已装备”标记

用户反馈手动穿齐保存的护甲后，轮盘没有“已装备”。进一步确认预设正常可用，并非显示“缺失/无法区分”。没有该角色的最新库存实例，具体额外装备或同款实例情况仍需游戏内确认。

## 原因与修正范围

Entries在每次打开功能轮盘/进入装备分页时重新读取真实库存，并非根据“最后点击的预设”判断。原Wearing同时要求所有解析出的保存实例已穿戴，以及库存中全部非盾牌护甲穿戴数量与预设件数一致。额外首饰、其他模组的隐藏护甲配件等会使第二个条件失败，即使整套预设已经穿齐。可以在纯逻辑测试中复现；手动穿戴来源本身没有被区别对待，完全相同的集合原本就能识别。

新增WearingPieces，仅检查非空匹配列表中的保存实例全部已穿戴，带候选索引边界保护；Entries的equipped标记改用该条件。仍先Resolve检查完整实例签名，无UID等价副本沿用0.4.5规则；穿戴同base的不同UID/强化/附魔/名称副本，不会冒充已穿戴保存项。多个有重叠装备的预设可以同时显示已装备。

Apply的removeOnly分支、Tick最终校验继续使用Wearing：要求整个受管理集合完全一致。如果有额外衣物，点击标记为已装备的预设仍按既有规则卸下受管理装备后重新穿上预设；没有额外衣物时，再点执行全卸。不增加或扩大卸装范围，武器/盾牌、任务物品和槽位保护保留。FWO/co-save、配置和翻译没有变化。

本轮没有增加每帧扫描、事件监听、缓存或游戏地址/hook，生产绘制代码不变。读取源仍为游戏线程库存快照，与玩家手动、其他模组或本轮盘穿戴共用相同判断。

## 验证

OutfitTests通过：手动穿齐且库存乱序/有备用副本、额外首饰/隐藏护甲类饰品保留标记且完整事务仍要求替换、少穿一件清除标记、穿戴不同实例不能假标记、重新手动穿回恢复、空列表和非法候选索引不标记。既有64件边界、重复UID/配方拒绝、序列化、0.4.5副本匹配和诊断回归通过。

Release成功自动部署。RuntimeLayoutTests的五种模拟运行时布局、地址库格式1/2/5夹具及实际0.4.6 DLL导出元数据检查通过；安装DLL与构建产物SHA256一致，8个主INI/语言/主题/meta文件精确哈希保留。本轮不改变绘制和地址访问，不重复离屏渲染或真实地址库全扫描；本地测试不能代替真实手动装备/模组附加装备实测。

请测试手动穿齐→开盘、加首饰、卸一件再开盘、重新穿回，以及精确整套点击卸装/额外衣物点击换装。如果正常可用且未显示标记仍出现，请提供预设名、新日志及是否存在同款不同实例/额外配件；不要仅为让标记出现而放宽身份匹配。
