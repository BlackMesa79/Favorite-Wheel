# 实时角色试穿：Apparel Preview 参考调查

日期：2026-10-04（Asia/Hong_Kong）。用户明确偏好自动、实时、匹配当前角色外观的装备预设预览。后续方案以此为目标，原静态照片评估保留为历史资料，不继续把手动拍照作为默认路线。本次为源码调查和实施设计，尚未增加 hook、角色预览或新 DLL。

## 排期与目标

2026-10-04 用户要求将研究整理为文档，先推进更急需的 UI 美观度。本文作为后续开发设计保留，实时试穿暂不实施；UI 路线比较与美化建议见 [UI_RENDERING_OPTIONS.md](UI_RENDERING_OPTIONS.md)。当前发布基线仍为 0.3.2。

目标体验：在功能轮盘的装备预设分类中，鼠标稳定悬浮某个预设后，轮盘旁自动展示当前玩家穿着整套预设的外观。无需手动拍照，不改变真实穿戴、背包和装备属性；关闭或离开预设时可靠恢复。以当前角色脸、发型、肤色与体型为基础，但装备网格自身的体型适配仍由对应装备和 BodySlide 构建决定。

首版研究不包含持续角色动画、暂停时完整物理模拟或对所有外观模组的兼容承诺。独立侧边角色窗口需单独完成渲染验证，不能将参考模组的主相机调整当成已经完成的侧窗功能。

## Apparel Preview 的真实路径

1. PreviewSession 保存待预览 ARMO 集合，带槽位和行身份键；普通切换可累计多件，鼠标自动模式一次替换成一件。快速鼠标请求用 generation 丢弃过期任务。
2. BipedHooks 包裹引擎的玩家衣物重建过程，先执行原穿戴模型生成，再对预览集合调用衣物附加模型生成函数。另一个 hook 把试穿槽位加入原穿戴槽位掩码，影响皮肤、头发/头部件隐藏。部分重叠外观由引擎的槽位替换完成。
3. REAugments 通过设置装备变化标志并刷新 AIProcess 的装备模型主动重建，不经 ActorEquipManager 真正装备物品。必要时推动玩家场景图更新，以在暂停菜单看到结果。不能把模型刷新标志误解为没有任何引擎状态变化；它改变的是实际玩家当前显示的 3D，清理和其他显示模组的协调仍然重要。
4. 预览关闭时清空集合并重建实际穿戴外观。生命周期还处理原菜单关闭、读档、实际装备事件及其他外观编辑器的占用。
5. 代码使用当前玩家的种族、性别与第三人称 biped 来挂接衣物。这比从 NPC 基础模板创建新 Actor 更有利于保留实时捏脸和角色身份，但没有证明所有 RaceMenu morph、动态染色或物理效果均已适配。

相关源码：[BipedHooks.cpp](https://github.com/maartenharms/apparel-preview/blob/8a9e7d7878422dbb1ff52f71abf223e7ab285e01/src/BipedHooks.cpp)、[REAugments.cpp](https://github.com/maartenharms/apparel-preview/blob/8a9e7d7878422dbb1ff52f71abf223e7ab285e01/src/REAugments.cpp)、[PreviewSession.cpp](https://github.com/maartenharms/apparel-preview/blob/8a9e7d7878422dbb1ff52f71abf223e7ab285e01/src/PreviewSession.cpp)、[MenuWatcher.cpp](https://github.com/maartenharms/apparel-preview/blob/8a9e7d7878422dbb1ff52f71abf223e7ab285e01/src/MenuWatcher.cpp)。

没有找到通用的外部 Begin/SetOutfit/End 预览 API。其可见 SKSE 消息和 MenuStudio 导出解析用于协调另一个编辑器及物品模型显示，不等于外部可以调用 Apparel Preview 的内部 C++ PreviewSession。MenuWatcher 仅接受 Inventory/Barter/Container；FavoriteWheelMenu 不在支持集合中。不能直接模拟 C 键或调用 DLL 私有地址作为接入方式。

## 对原评估的修正

实时试穿不必从完整 Actor 副本入手，现有玩家 biped 的显示替换提供了一条具体路线。它能避免真实换装、背包变动、装备数值变化与由真正装备触发的动画。然而“当前玩家显示试穿”与“独立侧边窗口渲染同一个角色”仍是两个问题：Apparel Preview 主要解决前者，Show Player In Inventory 主要解决相机看到角色；两者本身没有自动给 ImGui 提供透明背景的全身角色纹理。

用户目标保持为：打开功能轮盘，悬浮整套预设，自动显示当前角色的试穿外观，不手工拍照。若侧边卡片使用专用离屏纹理，需额外设计相机、场景/骨骼状态、灯光、裁剪和渲染状态隔离；不能将屏幕截图或调整主相机称为独立角色窗口。

## 整套预设的差异

- 当前 FavoriteWheel Apply 先卸下所有受管理护甲/服装/首饰再穿预设，武器、盾牌、弹药不操作。试穿应显示同样结果：当前衣物中即使与预设完全不冲突，但不属于预设的项，也应从试穿外观隐藏；皮肤/裸体基础模型必须保留或正确恢复。
- Apparel Preview 的 `real | previewMask` 和先生成原穿搭再注入的行为是增量叠加，不能直接作为“完整预设”语义。例如预设没有项链，当前项链仍可能留在外观中。整套路径需要自己的有效显示集合、皮肤/头部件槽位逻辑与多件冲突判断。
- 武器/盾牌视觉保持方式需要明确；清理护甲时不能误清盾牌、种族皮肤、骨骼、头部模型或其他装饰节点。预设里的同槽重叠及多槽衣物不能按遍历顺序静默丢件。
- 当前预设持有附魔、强化、自定义名等实例信息；公开参考的衣物注入按基础 ARMO 挂模型，variantKey 主要用于行标识。实例材质、动态染色、DAV、幻化等差异需要单独查询/应用，否则应明确降级到基础外观。

## 拟议实现边界

### 预览请求与恢复

View/输入或 Present 只提交值型预览请求，包括存档 epoch、打开会话、槽位/预设 ID 和请求序号。保留约 150–250ms 悬浮停留阈值，每次稳定选择只重建一次；重复选择复用当前场景。新请求替代旧请求，准备完成时核验当前选择仍一致，避免快速划槽出现旧预设。

暂停期间需要可执行的模型更新入口。不能依赖已暂停的常规 PlayerUpdate 来处理悬浮请求，也不能笼统宣称所有 SKSE AddTask 都是某个模组接受的主线程。参考的 SKSE 任务路径只用于确认存在可研究的同步刷新机制；必须用本工程暂停菜单下的线程/更新日志实测。D3D Present 只读就绪场景/纹理，不进行库存扫描或盲目执行引擎衣物重建。

关闭、切分类、回中心、进入管理/设置、失焦、读档、角色失效均停止预览并恢复相机/实际外观；确认换装时先撤销显示层，再进入现有恢复暂停后的 Apply 队列。读档不持久化预览状态；新角色不得沿用旧 biped 指针或异步加载结果。建立明确资源所有权，不允许旧清理任务操作新角色。

### 角色显示路线

优先验证现有玩家模型试穿和恢复，随后为轮盘设计自身的角色呈现入口：

- 研究临时菜单相机能否把真实玩家放到轮盘旁，维持主场景显示、可恢复视角且不改位置。该方式无需玩家副本，但有环境遮挡和相机模组协调问题，是机制原型候选，不自动当作最终侧窗方案。
- 独立侧窗需要专用离屏渲染，将当前外观场景受控地呈现到纹理，再用现有 ImGui 侧卡片显示。研究深拷贝场景或独立 biped 时必须处理骨骼映射、NiSkinInstance、材质及 shader 引用和头脸/体型变化；简单 NiObject::Clone 或复制 ActorBase 不足以保证这些内容完整独立。
- 暂停状态下静态站姿已能实现“当前捏脸、自动试穿”的核心效果。持续动作、旋转、头发和衣物实时物理属于额外范围；没有暂停更新机制时不保证物理继续模拟。

不增加 SKSE Menu Framework 或 Apparel Preview 的硬依赖。若后续选择外部公共接口方案，先证实接口确实存在、覆盖自定义菜单与全套语义、稳定且兼容两版；目前未找到这种接口。

## 兼容重点

当前玩家的脸、肤色、发型、性别和种族应优先沿用现有 3D。装备仍须有适用于当前种族/性别/体型的 ARMA 和网格；这不能把未构建 BodySlide 的衣服自动拟合任意体型。需要验证 RaceMenu morph/骨骼缩放/皮肤材质、3BA/BHUNP/UBE、头盔与发型隐藏、SMP、幻化及 DAV，不承诺完全适配所有组合。

公开源码明确针对 Helmet Toggle/DAV、Fitting Room 做特殊处理，且遇 Skyrim Outfit System 同类管线冲突时禁用。轮盘若独立实现同类模型 hook，也需协调或安全禁用；安装两套渲染注入实现不能仅靠加载顺序假定兼容。用户当前安装目录可见 ShowPlayerInInventory、MenuStudio、FittingRoom，后续原型需要用这些实际组合验证。

参考里 SE 与 AE 的衣物重建调用位置不同，AE 还有原调用被内联的情况。1.5.97 和 1.6.1170 必须分别检查实际调用契约和原指令；不可照抄参考偏移宣称适配完成。保留本项目两版精确运行时范围。

## 原型验收顺序

1. 默认关闭的研究预览入口：轮盘暂停时显示当前玩家全身，关闭/失焦/读档恢复视角，实际玩家位置、穿戴和属性无变动。
2. 单件衣物外观替换：验证当前脸/体型、未实际装备、关闭恢复；无装备事件、数值或动画副作用。
3. 完整预设：一次提交整套显示集合，移除旧服装/首饰的显示，保留皮肤和武器/盾牌语义，拒绝缺失/冲突，不串预设。
4. 侧边布局、适当缩放/旋转和渲染路线验证；检查 CS/ENB、帧时间、显存、快速悬浮和资源释放。
5. 两版与当前外观模组回归；实测通过后再提供默认启用的测试构建。
