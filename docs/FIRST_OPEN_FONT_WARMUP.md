# 首次开盘字体预热测试

2026-10-25。用户反馈首次按 Q 后有可感知延迟。

用户后续游戏内复测确认：本次首次打开轮盘相比之前明显更快。保留当前优化；该反馈证明体感改善，不代表所有新增字形或分辨率变化场景都无卡顿。0.8.0 正式压缩包仍未更新此优化。

此前保留的 02:33 会话日志中，目录扫描 0.04 ms，首次开盘字体生成/上传 212.322 ms，首帧 CPU 213.907 ms；后续普通开盘无字体重建。领主新增文字时仍有约 121 ms 重建。当前实时日志尚未包含本次开盘，所以该证据来自之前实际测试会话，不表示已经复现本次完整延迟。

本次将本地化 UI 字体预热放在渲染器初始化中，按既有 engine UI framebuffer 尺寸选择字号，缺失时使用 swap-chain buffer。字体 GPU 资源在首次轮盘操作前上传。保持渲染路由、字形质量、字号和按需新增字形逻辑不变。

预热只移动原先的初始化成本，并非消除它；首次遇到目录独有字形或输出尺寸/语言/主题变化仍可能重建。这是冷启动路径的改善，不宣称已彻底消除首次开盘延迟。

Release 构建通过。独立 WheelPreview startup-font zh_CN classic 测试使用 WARP，1280x720：UI 图集生成并上传，已有字形首次开盘不重建，预热约 147.655 ms。该测试不绘制画面、不代表视觉或游戏内验证。

测试 DLL 自动部署，产物与安装哈希一致：0DFCF0C3F8B945DEC64615C652D835F7BA2B54DB6BCFA14A83D290E6AB3ECE48。原 DLL 位于 build/backups/first-open-font-*，18 份 INI 不变。dist 中已验证的 0.8.0 正式包未重打。

重启游戏后检查首次 Q 的延迟和日志 Startup UI font warmup、Native-size font atlas、Wheel transition。若首开仍重建且耗时较高，应继续针对目录新增字形处理，不能只将更多同步工作移动到普通游戏帧。
