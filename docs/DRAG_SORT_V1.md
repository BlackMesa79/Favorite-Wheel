# 手动排序拖拽第一版

Shift+T 进入手动排序后，指向条目按住左键，移动超过 0.05 个标准指针单位进入拖拽。拖到已有条目的扇区松手，把原条目插入目标位置，中间条目顺移，不是简单互换。物品身份与原自定义排序一致，同身份行仍共享排序位置。

短按左键在松开时前移一位；右键后移；拖拽期间右键或 Esc 取消本次拖拽，编辑模式保留。按住左键滚轮跨页可继续拖拽，分页不会重置指针，且会强制进入拖拽状态以免松开误作短按。中心、空扇区、同一条目松手不更改顺序。第一版不支持跨分类拖动，不在空扇区追加。

切换分类／轮盘、退出编辑、设置、关闭、失焦等流程清除或拒绝拖拽；目录刷新清除拖拽，防止源或目标变化后的错误落位。左键释放即使被 InputGate 标记为已捕获，也会在过滤前交给拖拽结束逻辑；排序期间不装备、施法或消耗物品。保存游戏才持久化最终顺序。

视觉反馈：源条目淡化，图标和名称卡片平滑跟随指针，目标外缘高亮脉冲，松手后卡片归位并淡出。顺移的其他条目在提交时更新，暂未加入逐扇区绕行动画。关闭动画时保留源淡化、目标标记与跟随卡片，立即结束归位反馈。运行时不改用户动画开关。

测试：InventoryOrderTests 覆盖前／后插入、中间顺移、跨页、同一条目／消失身份无操作、拖动阈值、取消及分页避免误点击；WheelLogicTests、SettingsTests 和语言迁移测试通过。WARP 实际渲染并目视检查中文 classic 拖动状态、英文 skyrim 关闭动画状态、归位后状态；另输出释放中间帧。

## 松手重复加锁修复

用户 2026-10-25 23:16:49 日志报告 std::system_error / resource deadlock would occur，概率调用栈包含连续 FavoriteWheel 帧。代码确认 EndSortDrag 持有 viewMutex 时调用 ValidPlayer，后者通过 IsOpen 再次锁定同一非递归 mutex。修复将 Focused／ValidPlayer／形态检查移到获取 viewMutex 之前，仍持有 lifecycleMutex；视图状态检查与落位更新继续在 viewMutex 内。

本问题说明此前排序模型测试和渲染预览没有覆盖真实输入处理的锁调用链。此次审查了落位链：排序状态锁在 InsertItem 返回时释放，之后才 ResortInventory；短按移动在 viewMutex 作用域结束后执行。未通过更换递归锁或吞异常掩盖问题。

InventoryOrderTests、WheelLogicTests 通过，构建和自动部署完成，DLL 哈希与主配置保持情况记录在 build/drag-release-fix-verification.txt。尚未游戏内验证；建议重启游戏后先测同页拖拽松手、短按前移，再测跨页落位及右键取消。
