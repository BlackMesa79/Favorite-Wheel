# 空分类与渐进替换换装（0.5.2测试版）

2026-10-09：以正式0.5.1为基准的新迭代。历史GOG测试也曾标为0.5.2；此文对应当前空分类/换装改动，不能与历史测试包混用。

## 空分类

2026-10-10追加“游戏行为 / 隐藏空分类”设置，General/HideEmptyCategories默认1。关闭后标题与导航显示原八类，包括空页；应用后用现有目录重建可见集合，不重新扫描库存。功能轮盘装备预设及可选面光的可见规则保持独立。用户已确认此前空分类、换装及预设闭盘正常，新设置验证见SETTINGS_REFINEMENTS_0.5.2.md。

收藏轮盘仅显示当前来源中存在条目的类型；收藏模式依据收藏，全背包模式依据原有全背包目录（魔法仍只收藏）。原有八类顺序不变，A/D、左右方向、手柄分类按键和标题栏都使用同一可见集合。标题仍最多五项、当前居中并加尖括号。

InventoryPages.Set利用已计算的分类边界生成八位掩码。切换、绘制、View快照只做最多八类的固定小循环，仍只复制最多十条可见项目，没有额外游戏库存扫描。目录刷新后同步更新掩码，物品增加时类别恢复；当前类别变空时选择原顺序中下一个有物品的类别并回到第一页。仍存在的记忆类别与页码保持，页码按新条目数夹紧。只有一类时切类型不复位页码或光标。

全部为空仍允许开盘，保留“没有收藏/没有库存”空状态并可进入设置、功能轮盘；标题栏不显示空类型标题/类型切换提示，不自动关闭。不改变背包收藏标记。功能轮盘的装备预设分类保留（含保存/导入入口），面光仍按公开API可用性显示。

正常手动切类型保持光标；动态目录刷新若同一扇区的物品身份已变，沿用已有安全逻辑清除选择，避免误用新条目。

## 换装

用户明确选择逐件替换，放弃“先全脱、再全穿”的中间过程；最终集合与重复点击卸装语义保持。完整匹配预设时仍全卸，额外衣物存在时只清理目标外衣物。

1. 沿用完整预设解析、精确身份、任务装备保护和盾牌冲突检查。
2. 保留已经穿戴的目标实例，不卸下/重新穿戴共同装备。
3. 对未穿戴目标，将原生Body（32）槽位物品稳定排到最前，其余按预设顺序穿戴。冲突槽位交给原生EquipObject处理。
4. 观察全部目标已穿戴后才清理原穿搭中目标外的装备。已被原生槽位替换卸下的物品直接跳过。
5. 最后验证严格完整集合；完整预设再点击仍只卸装。不改变存档格式、数量限制、武器/盾牌/弹药范围。

仍只在原SKSE任务线程调用原生装备接口，无后台线程穿戴、模型隐藏或引擎补丁。每次Tick最多提交两次原生调用，软预算3ms；已经观察完成的步骤可以当次继续，无固定16ms等待，也不再人为要求提交/确认各占一整个更新。16次状态检查上限避免大量已卸配件同帧遍历。若原生调用延迟，仍最多等待750ms且不重复提交，总任务15秒超时。

预算不能中断单次原生调用或库存查询；一次缓慢身份查询允许提交第一项以免永久饥饿，之后不追加调用。验证扫描超过预算时让出后续处理。大型模型、第三方装备脚本和场景帧时长仍影响实际速度，不能承诺每帧硬性小于3ms或视觉零裸露帧。新流程消除了插件主动制造的整套全裸等待阶段，而原生同槽替换及异步3D刷新仍非原子。目标穿戴失败时不开始清理旧配件，已替换部分不强制回滚。

应用或卸下装备预设时始终关闭轮盘，再由原队列等待菜单与暂停释放后执行换装，方便观察或录制完整过程；不受KeepOpen影响。普通物品装备、法术和面光操作仍按原KeepOpen设置。预设右键管理、创建和导入保持原页面行为。失焦/菜单/死亡/读档按已有生命周期取消，不自动重开轮盘。
