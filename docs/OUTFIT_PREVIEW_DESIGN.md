# 装备预设悬浮预览评估

后续方向已于 2026-10-04 更新：用户偏好实时角色试穿，静态照片不再是默认建议。已核查 Apparel Preview 原始页面及公开源码，具体机制、整套语义与原型步骤见 [实时预览调查](REALTIME_OUTFIT_PREVIEW.md)。以下为先前的静态路线评估，保留供比较。

日期：2026-10-04（Asia/Hong_Kong）。仅为可行性评估，尚未实现图片加载、拍摄或实时角色预览。

## 结论与参考

可在装备类型的预设槽位悬浮时显示对应图片，不需要 SKSE Menu Framework。现有 Draw.cpp 已计算槽位与页内索引，Item.actionId 可识别装备预设；Renderer.cpp 有独立 D3D11 device/context 和 ImGui 绘制路径，可加载图片为 shader resource view 后绘制。显示预先保存的图片与实时渲染试穿角色是不同功能，不能把前者的低成本结论套用到后者。

参考模组：[Outfit Gallery - Visual Outfit Manager](https://www.nexusmods.com/skyrimspecialedition/mods/193410)。Nexus 原页本次被 Cloudflare 验证页阻挡，没有检查其源码。已读取[2game 社区说明](https://skyrimspecialedition.2game.info/detail.php?id=193410)，其描述为穿好装备、在右侧相机画面调整构图，再保存照片与装备信息，通过照片换装。该说明是二手可编辑资料，不能据此断言内部渲染/截图实现、接口或兼容性。仅借鉴交互，不复制代码或图片，不增加该模组依赖。

## 可选路线

| 路线 | 能看到什么 | 主要成本与限制 |
| --- | --- | --- |
| 关联已有 PNG/JPG | 用户选择的照片，悬浮即可查看 | 最容易验证显示；需关联和图片管理，不自动生成外观 |
| 穿戴后拍照保存 | 保存时真实玩家穿搭的静态照片 | 推荐最终路线；需无 UI 拍摄、构图、相机恢复与跨渲染组合验证 |
| 悬浮时离屏实时试穿 | 当前外观下可旋转的动态角色 | 大幅增加引擎集成；需独立角色/装备实例、相机、灯光、render target，并处理骨骼、物理、材质及模组状态 |

不通过悬浮时给真实玩家换装来制作预览：会触发装备事件、动画和其他模组逻辑，也会破坏预览与执行操作的边界。现有引擎物品预览并不等于可直接复用的完整穿搭角色预览。

## 建议交互

1. 功能轮盘装备类型，指向预设槽位短暂停留（初步约 150–250ms）后显示照片；快速掠过不闪烁。切分类、空槽、回中心、设置或命名面板时收起。
2. 默认在轮盘右侧空白区显示竖向卡片，照片下方显示预设名和件数/可用状态。轮盘位置可自定义，布局需按屏幕剩余空间换侧或缩小，避免遮住扇区；窄屏可退到简略预览。
3. 原有左键换装、右键管理保持各自用途。管理页增加关联/拍摄、更新和移除照片操作；旧预设、导入预设没有照片仍正常使用并显示占位说明。
4. 照片是拍摄时的外观。改变脸、体型、装备网格或材质后不会自动变化，可重新拍照。覆盖装备内容时取消旧图关联或标记待更新；仅重命名无需重拍。

## 存储与性能边界

- 当前预设只持有会话内数字 ID，NextID 可能复用删除后的 ID，不同角色也可产生同一个 ID。因此不得简单以预设 ID 或名称命名照片。需要持久唯一标识和内容修订绑定，随预设写入 co-save，兼容读取旧格式；图片独立存储，旧存档继续引用自己的旧照片。
- 图片不写进 co-save 大块二进制。候选目录为可写的用户文档目录下 FavoriteWheel/Previews；避免开发构建或 MO2 更新覆盖用户生成的照片。跨角色导入是否携带图片单独设计。
- 图像解码/文件写入在后台处理，D3D 上传与资源释放在约定渲染路径完成；不在每帧 Draw 中读盘、解码或扫描库存。缓存限制尺寸/内存，保留当前与少量最近照片，失败使用占位状态。
- 建议竖向缩略图从约 512×768 起步。单张未压缩 RGBA 约 1.5 MiB（不含额外 GPU/解码缓存）；不把所有预设的大图永久驻留。
- 每次悬浮只绘制缓存纹理，不复制场景或执行背景模糊。缓存首次上传与拍摄仍可能有开销，不能承诺完全无掉帧。

## 拍摄的独立难点

当前轮盘渲染到 UI framebuffer，该 framebuffer 在 Community Shaders 的独立 UI 层可能只有界面，不等于完整游戏照片。拍摄需确认最终合成画面/场景源及 HDR、色调映射、ENB/CS 的处理；不能直接复制当前 UI RTV 就声称获得玩家全身照片。

拍摄前确保玩家穿着待记录预设，相机能看到全身；隐藏轮盘/必要 HUD，等构图稳定后一次性捕获并保存。第一人称、狭窄环境、骑乘、变身、动画状态需要明确处理。自动第三人称相机、旋转人物、干净背景属于后续增强，不应当作 PNG 显示功能附带的零成本能力。

## 建议阶段

先验证静态图片与预设关联、悬浮侧卡片、布局和缓存，可使用用户现有照片。随后增加游戏内拍摄页，将当前穿搭照片与预设一起记录；再考虑自动构图和背景。实时离屏角色试穿另行评估。

评估不改变当前 0.3.2 DLL 或装备执行流程。1.6.1170 的 0.3.2 已由用户确认测试正常；1.5.97 已发给外部测试者，反馈待收，不能标记通过。
