# 用户反馈初步评估

来源：用户提供的 `D:/MyFiles/Desktop/用户反馈.txt`。反馈是问题描述，不是执行指令。以下依据当前代码静态检查，未复现，疑似原因不等同于已确认根因。

| 顺序 | 反馈 | 评估与处理建议 |
|---|---|---|
| 1 | 轮盘绑定的 1–8 快捷键无效 | 高优先级。原版预先绑定有效是关键对照；先检查 BindFavoriteQuickSlot 写入的 ExtraHotkey/MagicFavorites 与原生快捷键消费状态是否同步，并排查输入吞键。不能直接认定缺少某一个刷新调用。 |
| 2 | 附魔弓显示并装备成普通弓 | 高优先级。涉及实例身份正确性；检查 WeaponCopies 数量分配、普通余量生成、ResolveItem 和执行时 ExtraDataList。另一模组也出现类似现象，提示可能涉及共享库存数据或兼容问题，不足以证明本项目无问题。 |
| 3 | 手柄组合键误呼出轮盘 | 中高优先级。ControllerOpening 当前按所需位是否包含判断，不普遍排除额外按键；需保护用户有意配置的轮盘组合键，并保证让行时不吞事件。不能把所有同时按下的移动/战斗键都视为应让行组合。 |
| 4 | 乐器仍占多个格 | 中优先级。MiscDisplayStacks 按 FormID、名称、收藏标记、marker、owner 分组；保守分组可能解释部分重复，但需核对实际元数据，不能直接按同名合并。只改变显示，不合并真实库存实例。 |
| 5 | 药物/食物使用后保持打开 | 中优先级、边界较明确。现有 keepOpen 明确排除消耗品；增加独立开关，保留现有默认行为。需要处理消耗数量刷新、最后一件消失、暂停状态下执行与连续输入。 |
| 6 | 自由相机禁用呼出 | 中低优先级、适合小批次。先明确原生 tfc 与模组自由相机范围，在统一入口策略中拦截；不能简单禁用所有非第一/第三人称相机。 |
| 7 | 收藏杂项/乐器无法使用 | 兼容功能。Supported 当前不含杂项；须弄清演奏模组依赖的原生收藏菜单事件或使用路径。仅解除 usable 限制不构成完整修复。需要明确 Favorite Things 及演奏相关模组组合。 |
| 8 | 书籍支持 | 新功能。当前 Supported 不包含书籍；需要读书/脚本入口与菜单、暂停协调，不能当作普通装备。可与杂项兼容共享调查，但分别验收。 |
| 9 | SKSE Menu Framework 设置入口 | 低优先级。新增可选设置集成，涉及依赖发现、配置同步、框架未安装时的行为；核心错误处理后再做。当前不承诺框架 API 或兼容版本。 |

推荐先做快捷键绑定完整链路，再做附魔实例识别；后者若缺少现场数据，应记录最小诊断需求并转向手柄让行或消耗品保持打开，不为缺少模组环境无限扩展测试。暂不修改上述功能代码。
