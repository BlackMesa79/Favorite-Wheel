# I4 图标库接入方案

- Task ID: 20261110-i4-icons
- 状态: APPROVED（2026-11-10 用户确认；第一期 IN_PROGRESS）

## 1. 背景与目标

社区背包图标库（B.O.O.B.I.E.S、Handy Icon Collection、Rotols More Icons 等）通过 Inventory Interface Information Injector（下称 I4）的 JSON 规则，为物品指定 `iconSource`（SWF 路径）、`iconLabel`（SWF 帧标签）和 `iconColor`。轮盘使用 ImGui 绘制，无法直接显示 SWF。

2026-11-10 的离线验证（见 [I4_ICONS.md](../I4_ICONS.md#2026-11-10-离线验证结论)）确认：图标 SWF 只包含静态矢量形状与少量位图；修好 mip 采样后，缩小显示的边缘平滑；图标几乎都是单色，转成白色遮罩后可以按任意颜色着色。

目标：在不依赖 Scaleform 运行时、不分发第三方美术的前提下，让轮盘里的物品显示与背包一致的 I4 图标，并提供跟随主题色、I4 原色、保留原图三种配色。

## 2. 范围

### In Scope
- 运行时读取已加载插件对应的 `SKSE/Plugins/InventoryInjector/<插件>.json`，按 I4 语义匹配规则。
- 在游戏线程生成快照时，为每个物品构造与 SkyUI 条目等价的字段，并算出最终的 `iconSource` / `iconLabel` / `iconColor`。
- 自研轻量 SWF 读取与矢量栅格化：通过游戏资源系统读取（覆盖 MO2 松散文件与 BSA），输出原色 RGBA 与白色遮罩两种纹理。
- 绘制优先级、三种配色模式、设置项、日志诊断、WheelPreview 场景、单元测试与离线真实素材对照工具。
- 物品（武器、防具、药水、书、杂项、灵魂石、弹药、卷轴、原料、火把）和法术、力量、龙吼。

### Out of Scope
- 调用 I4 的 DLL 或其 Scaleform 函数，或加载任何 SkyUI 电影。
- 时间轴动画、AS 脚本、滤镜、混合模式、文本与字体字形、变形形状（MorphShape）、LZMA 压缩（ZWS）SWF。遇到时整个图标回退并记录日志。
- I4 写入的非图标字段（如 `subTypeDisplay`）用于详情卡。可作为后续独立任务。
- 游戏内图标浏览器、热重载、编辑 I4 规则。
- 把任何第三方 SWF 或其衍生 PNG 放进仓库或安装包。

## 4. 技术方案

整体分成四层，层与层之间只传值类型：

```
游戏线程（快照）                 后台工作线程                    渲染线程
EntryBuilder ─► I4Rules ─► Item.i4 {source,label,color}
                                   │ 请求 (source,label)
SwfStore（游戏线程读取字节）──────►  SwfRaster（解析+栅格化）──►  I4Textures（上传 / LRU）──► IconLibrary::Find / DrawIcon
```

### 4.1 EntryBuilder：构造 SkyUI 等价条目

- 不使用 `GFxValue`，改用自有的小型属性包 `I4::Entry`：字符串键映射到 `null | bool | double | string | 关键词集合`。
- 先按 SKSE 扩展数据填入原始字段：`formType`、`formId`（运行时完整 ID）、`keywords`（以关键词 EditorID 为键的集合）、`partMask`、`weightClass`（护甲原始类型）、`weaponType`、`equipSlot`、`bookType`/`flags`/`teachesSkill`/`teachesSpell`、`gemSize`/`status`，以及魔法效果的 `school`、`resistance`、`actorValue`、`archetype`、`deliveryType`、`castType`、`spellType`、`effectFlags`、`effectKeywords`。
- 再逐个移植 SkyUI `InventoryDataSetter` 的 `processArmorClass/PartMask/Other/BaseId`、`processWeaponType/BaseId`、`processBookType`、`processAmmoType`、`processKeyType`、`processPotionType`、`processSoulGemType/Status/BaseId`、`processMiscType/BaseId`，以及 `MagicDataSetter` 的对应逻辑，得到 `subType`、`weightClass` 等最终值。
- 只生成规则可能读取的字段。材质显示字符串、价格、重量这类展示字段不生成。
- 拆成两个函数：读取引擎数据的 `Collect(RE::TESForm*, InventoryEntryData*)`，以及只处理普通结构体、可离线单元测试的 `Derive(RawFields)`。

### 4.2 I4Rules：规则加载与匹配

- `kDataLoaded` 后加载一次：按 `TESDataHandler::files` 的顺序遍历已勾选插件，读取对应 JSON。文件和规则的顺序就是匹配顺序，这一点必须保持。
- JSON 解析允许注释，与 I4 使用的 JsonCpp 行为一致。键名以 `$` 开头的跳过。
- 移植以下匹配类型：`MatchProperty`（含数组元素任一匹配、`null` 语义）、`AnyOfProperty`、`RangeProperty`、`BitfieldProperty`、`KeywordsProperty`、`MainPartProperty`（含 `PartMaskPrecedence`），以及 `parts` / `mainPart` 写入 `partMask` 的转换。还要移植 `FormIDParser` 的 `插件|ID` 解析，含 ESL。
- 规则校验与 I4 一致：属性与赋值都不能为空。`iconSource` 指向的文件不存在时，删除 `iconSource` 和 `iconLabel`。只有 `iconLabel` 时，`iconSource` 视为 null，即 SkyUI 默认图标库。
- 处理流程严格按 `CustomDataManager::ProcessEntry`：
  1. 所有命中规则先写非图标字段。规则可以改写 `subType`、`weightClass`，从而影响下一步。
  2. 如果有规则写过非图标字段，清除 `iconLabel` 和 `iconColor`，再执行移植后的 `IconUtil::ProcessDefaultIcon`。
  3. 所有命中规则再写图标字段，后面的规则覆盖前面的。
- 性能：按 `formType` 与 `formId` 预建索引，未指定 formType 的规则进入公共桶，但不改变相对顺序。每个物品只检查可能命中的规则。目标：100 个物品的快照总耗时 < 1 ms；全背包模式 500 个物品 < 5 ms。日志输出实测值。
- 输出 `I4::Icon { std::string source; std::string label; std::optional<uint32_t> color; IconOrigin origin; }`，其中 `origin` 区分“由 JSON 规则显式赋值”和“只有 I4/SkyUI 默认图标”。

### 4.3 SwfStore 与 SwfRaster：读取与栅格化

- **读取**：在游戏线程用 `RE::BSResourceNiBinaryStream("Interface/" + source)` 读取整个文件，按 source 缓存字节（单个文件通常为 0.5–60 KB）。这条路径覆盖 BSA、MO2 和松散文件。快照生成时只登记需要的 (source, label)，读取通过 SKSE 任务接口分批完成，不阻塞快照。
- **解压**：FWS 直接使用；CWS 用 zlib inflate；ZWS 不支持，回退并告警。
- **解析的 tag**：DefineShape1–4（含样式切换和新样式数组）、DefineSprite、PlaceObject/2/3（矩阵、颜色变换、深度、替换）、RemoveObject/2、ShowFrame、FrameLabel、DefineBitsLossless/2、DefineBits/JPEG2/JPEG3 与 JPEGTables（JPEG 用 WIC 解码，项目已链接 `windowscodecs`）、End。DoAction/InitAction 忽略。其他 tag 记入“不支持”统计。如果某个图标用到不支持的字符或特性，该图标回退。
- **帧定位**：在主时间轴中找到 `label` 对应的帧，从第 1 帧开始重放显示列表直到该帧，与 SkyUI `gotoAndStop(label)` 的结果一致。子 sprite 取第 1 帧。标签比较与 SWF 原文一致，不去除末尾换行（I4 规则里写的也是原文）。
- **几何**：把 SWF 的 fill0/fill1 边转换成每个填充样式各自的闭合路径（标准的边收集与首尾拼接算法），线条样式转为描边。四舍五入后首尾相同的点视为闭合。
- **光栅化**：使用 PlutoVG（MIT，C 语言实现）。它支持抗锯齿、非零与奇偶填充规则、纯色、线性与径向渐变、位图填充、变换和描边。SWF 渐变的 256 比例点和 spread/interpolation 模式按规范映射，不支持的组合退化为最接近的模式并记录。
- **边界与尺寸**：使用该帧显示列表的实际几何边界（第一轮验证发现舞台画布会裁掉图案），等比缩放到最长边约占画布 90%，居中到正方形透明画布。画布边长按当前最大图标像素尺寸 × 2 取整到 64、128 或 256，不超过 256，生成 mip。
- **两种输出**：
  - 原色：颜色变换照常应用。
  - 遮罩：栅格化时把所有填充、描边、位图的 RGB 强制为白色，只保留 alpha 与颜色变换中的 alpha 乘数。在矢量层面改色，不对位图做后处理，避免边缘出现颜色残留。
- **数值与资源上限**（第一期第四轮加固，见 `build/i4-phase1/round4/REPORT.md`）：
  - 路径在 SwfRaster 内以 double 精度直接变换到设备像素坐标，每个点检查有限且 |坐标| ≤ 16384 px 后才转成 float 交给 PlutoVG；PlutoVG 只收到单位矩阵。嵌套 sprite 的累计矩阵、视口、描边宽度同样要求有限，否则该图标失败回退。
  - 描边边界按 cap/join 计算：方端取 √2·w/2，miter 取 miterLimit·w/2，再乘实例矩阵的最大奇异值；低于 1 px 的描边按 1 px 下限重新外扩一次。
  - 单次 Render 预算：时间轴重放 4096 个 op、单路径 131072 个设备点、全帧 262144 个设备点、160 次整画布扫描（每条路径 1 次，渐变另加 0.25 次）。实测 BOOBIES、Handy、留出集的最大值分别为 305 个 op、43810 个点、66 次扫描。
  - PlutoVG 的所有 malloc/calloc/realloc 通过强制包含的 `include/third_party/plutovg_checked_alloc.h` 改为检查返回值，失败时 `__fastfail` 立即终止，而不是在空指针上继续写入。上游源码不改动；在预算内，单次分配不超过几 MiB，只有游戏进程本身内存耗尽时才会触发。

### 4.4 I4Textures 与绘制集成

- **纹理缓存**：渲染线程每帧最多上传 4 张，避免卡顿。缓存键为 `(source, label, 变体, 边长)`，按纹素预算做 LRU（默认 32 MB 含 mip），快照中正在使用的图标不会被淘汰。设备重建时清空，再按当前快照重新请求。
- **磁盘位图缓存**（2026-11-10 用户确认）：转换后的位图写入磁盘，下次启动直接读取，不必重新栅格化。
  - **位置**：`<游戏根目录>/Data/SKSE/Plugins/FavoriteWheel/IconCache/`，用 `GetModuleFileNameW` 取游戏 exe 目录拼接，与主 INI 的定位方式一致（`src/Settings.cpp:25`）。不使用公共的 `My Games`，避免不同 MO2 实例或配置文件共享同一份缓存。在 MO2 下，新文件会落到 overwrite 文件夹（或用户设置的输出 mod），这是预期行为，README 需要说明。
  - **缓存内容**：只缓存 `Swf::Render` 输出的非预乘 RGBA（原色与遮罩两种变体）。不缓存 GPU 纹理和规则匹配结果：后者依赖运行时关键词（KID 等），每次启动重新计算。
  - **键与失效**：键为 SWF 文件内容 SHA-256 + 帧标签原文 + 变体 + 边长 + `SwfRaster` 转换器版本号。每次启动仍通过游戏资源系统读取 SWF 算哈希（文件很小），图标库更新后自动失效；修改栅格化逻辑时必须递增版本号，使旧缓存全部作废。不依赖文件修改时间，因为 BSA 与 MO2 虚拟文件系统里的时间不可靠。
  - **格式**：每个 SWF 哈希对应一个文件 `<sha256>.fwic`。文件头含魔数 `FWIC`、格式版本、转换器版本和条目表（标签、变体、边长、偏移、长度、CRC32），像素数据用 miniz 压缩。写入时先写临时文件再原子重命名；同一时间只有一个后台线程写入。
  - **读取校验**（缓存文件属于不受信任输入）：魔数和版本必须匹配；条目边长 1–256，宽高与边长一致；解压后长度必须精确等于 w×h×4，CRC 也要匹配；条目数和文件大小有上限。任何一项不合格都丢弃整个文件并重新转换，只写一次 warning。
  - **容量**：默认上限 64 MB（`I4IconCacheMB`，8–512），超出按最近使用时间删除，最近使用时间记录在索引文件或文件 mtime 中。
  - **失败处理**：缓存目录不可写（例如只读安装目录）时，退化为仅在内存中缓存，写一次 warning，功能不受影响。
  - **清理**：设置面板提供“清空图标缓存”按钮；主 INI 的 `I4IconCache=0` 可以完全关闭磁盘缓存。
- **未就绪时**：纹理还没准备好时直接画现有回退图标，不等待，就绪后的下一帧切换。
- **`IconLibrary::Find` 新顺序**（功能按钮不参与 I4），完整规则见 4.4.1：
  1. 主题图标包 `[Forms]` 按物品映射。
  2. 主题图标包 `[I4]` 对 I4 图标的重绘（规则图标或默认图标都适用）。
  3. I4 规则图标（`origin=Rule`）。
  4. 主题图标包分类 / `magic`。
  5. I4 默认图标（`origin=Default`，即 SkyUI 默认图标）。
  6. 内置图标。
- **三种配色**（`I4IconColor`）：

| 模式 | 纹理 | 着色 | 悬停/选中 |
|---|---|---|---|
| `Theme`（默认） | 遮罩 | 与内置图标相同的主题 ink | 与内置图标完全一致 |
| `I4` | 遮罩 | `iconColor`；规则和默认逻辑都没给颜色时用主题 ink | 保留颜色，悬停/选中由扇区高亮表达；可选亮度 +15% |
| `Original` | 原色 | 不着色，只乘界面透明度 | 同 `I4` |

  `Image` 结构增加 `color` 字段（或改为传最终颜色），`DrawIcon` 中 `tint ? ink : 白色` 的判断扩展为上表的三种情况。

#### 4.4.1 主题图标包与 I4 的关系

分工：I4 回答“这个物品是什么”（由用户安装的图标库决定），主题图标包回答“这一类东西在这个主题里长什么样”（由主题作者决定）。两者分层叠加，不互相替代。

- **没有图标包的主题**（含所有内置主题）：I4 规则图标 → SkyUI 默认图标 → 内置图标。安装了图标库后，轮盘与背包的图标完全一致。
- **有图标包的主题**：
  - `[Forms]` 仍然最高。这是对单个物品的显式指定。
  - **新增 `[I4]` 段**：按 I4 的 `source|label` 指定替换图片，格式为 `skyui/icons_item_psychosteve.swf|default_weapon=my_weapon`，右侧引用 `[Icons]` 中的键。主题可以用自己的美术统一重绘 SkyUI 默认图标或某个图标库的个别图标，而不必逐个物品映射。`source` 比较不区分大小写，`label` 按原文比较。
  - **I4 规则图标高于图标包分类**：图标库作者专门为某个物品画的图标，比主题的“剑”通用图标更具体。
  - **图标包分类高于 SkyUI 默认图标**：主题作者特意画的分类图标，比 SkyUI 的通用默认图标优先。
- **配色一致**：图标包 `|tint` 图标与 I4 遮罩都用主题 ink 着色。在 `Theme` 配色模式下，两者混用时颜色规则相同。`[I4]` 段替换的图片沿用该条目在 `[Icons]` 中的 `tint`/`original` 设置，不受 `I4IconColor` 影响（主题作者的选择优先）。
- **主题可选声明** `I4Icons=Off`：主题 INI 中写这一项时，该主题不使用 I4（例如极简风格主题），用户全局开关仍然有效。省略时为 `Auto`。
- 资源限制沿用 [ICON_LIBRARY.md](../ICON_LIBRARY.md)：`[I4]` 条目计入每包 512 个条目的上限。

### 4.5 接口契约（Coder 与 Tester 共同依据，不得擅自更改）

```cpp
// include/I4Rules.h
namespace Wheel::I4 {
    struct Value;                                   // null|bool|double|string|keyword-set
    struct Entry { /* 有序属性包 */ 
        const Value* Get(std::string_view) const; void Set(std::string_view, Value); void Erase(std::string_view); };
    enum class IconOrigin : std::uint8_t { None, Default, Rule };
    struct Icon { std::string source, label; std::optional<std::uint32_t> color; IconOrigin origin=IconOrigin::None; };
    struct LoadReport { std::size_t files=0, rules=0, rejected=0; std::vector<std::string> warnings; };

    LoadReport Load(std::span<const std::pair<std::string,std::string>> pluginJson); // (插件名, JSON 文本)，可离线测试
    LoadReport LoadFromGame();                                                  // kDataLoaded，游戏线程
    Icon Resolve(Entry& entry);                                                 // 线程安全只读；会修改传入的 entry
}
// include/I4Entry.h
namespace Wheel::I4 {
    struct RawFields { /* formType, formId, keywords, partMask, armorType, weaponType, ... */ };
    Entry Derive(const RawFields&);                  // 纯函数，移植 SkyUI DataSetter
    RawFields Collect(const RE::TESForm*, const RE::InventoryEntryData*); // 游戏线程
}
// include/SwfRaster.h
namespace Wheel::Swf {
    enum class Variant : std::uint8_t { Original, Mask };
    struct Bitmap { std::uint32_t width=0, height=0; std::vector<std::uint8_t> rgba; };
    struct Result { std::optional<Bitmap> bitmap; std::vector<std::string> warnings; };
    struct Movie;                                    // 解析结果，不可变，可跨线程共享
    std::shared_ptr<const Movie> Parse(std::span<const std::uint8_t> file, std::vector<std::string>& warnings);
    Result Render(const Movie&, std::string_view label, Variant, std::uint32_t edge);
}
// include/Favorites.h  —— Item 新增快照字段

```

### 4.6 数据结构与设置变更

- `Item` 新增 `I4::Icon i4`。只是快照字段，不持久化，不影响存档和预设序列化。
- 主 INI 新增以下设置，默认值写在括号里。设置面板提供对应开关，并补全全部语言的翻译键：
  - `I4Icons=1`：没找到任何 I4 JSON 时自动无效。
  - `I4IconColor=Theme`：可选 `Theme`、`I4`、`Original`。
  - `I4IconScope=All`：`All` 让没有规则的物品也用 SkyUI 默认图标（需要安装 SkyUI，否则等同 `Rule`）；`Rule` 只用 JSON 规则显式赋值的图标。
  - `I4TextureBudgetMB=32`：取值 8–128。
  - `I4Debug=0`：为 1 时，每个物品输出一行匹配结果，包括 formId、source、label、color 和命中的规则（文件#序号）。
  - `I4IconCache=1`：磁盘位图缓存开关，见 4.4。
  - `I4IconCacheMB=64`：磁盘缓存上限，取值 8–512。
- 自动部署只补齐缺少的键，不覆盖用户已有值（遵守 AGENTS.md）。

### 4.7 错误处理

| 场景 | 行为 |
|---|---|
| JSON 解析失败 | 跳过该文件，日志写明文件名与错误位置，其他文件照常加载 |
| 规则无效（属性或赋值为空、iconSource 不存在） | 与 I4 相同：丢弃该规则，或只删除 iconSource/iconLabel；日志汇总数量 |
| SWF 不存在 / ZWS / 文件头损坏 / 被截断 | 该 source 标记失败，相关物品回退，同一 source 只告警一次 |
| 找不到标签 / 帧为空 / 用到不支持的 tag | 该 (source, label) 标记失败并回退，日志汇总各 source 的不支持 tag 计数 |
| 栅格化异常或尺寸异常 | 捕获并回退，不让游戏崩溃 |
| 变换溢出 / 坐标超出设备范围 / 超出 Render 工作量预算 | 该 (source, label) 失败并回退，写 warning；不返回内容错误的“成功”图像 |
| PlutoVG 内部内存分配失败 | `__fastfail` 立即终止进程（此时游戏本身已内存耗尽），不在损坏的堆上继续运行 |
| 纹理创建失败或超出预算 | 淘汰不在用的条目；仍然不够时回退并告警一次 |
| 设备重建 | 释放全部纹理，按当前快照重新请求 |

## 7. 风险点

- **字段推导和 SkyUI 不一致**，会导致轮盘图标与背包不同。这是最大风险。缓解：`Derive` 做成纯函数并覆盖每个分支；`I4Debug` 输出逐项结果；游戏内抽查对比。
- **SKSE `keywords` 字段的细节**（是否包含 KID 运行时分发的关键词、是否只读基础物品）需要对照 SKSE 源码确认。KID 关键词在运行时已写入表单，`Collect` 直接读表单可以覆盖。
- **SWF 特性超出范围**：Handy Icon Collection 有 1 个 DefineShape4 和若干位图，需要以 AC-4 的实测为准。不支持的部分回退，不追求覆盖全部 SWF。
- **游戏资源系统的线程安全**：读取只在游戏线程进行，解析和栅格化在工作线程，上传在渲染线程。
- **纹理与内存**：全背包模式图标多，依赖 LRU 和预算控制；日志输出峰值。
- **I4 版本差异**：本机安装的是 1.1.0，语义按 `52cc4cb` 移植。若规则数对照（AC-5）不一致，先查版本差异。
- **SkyUI 默认图标**位于 SkyUI 的 BSA 中，`I4IconScope=All` 必须通过游戏资源系统读取。未安装 SkyUI 时，这些规则会像在 I4 中一样被校验丢弃。
- **许可**：只在运行时读取用户自己安装的文件；I4 逻辑移植保留 MIT 声明。
