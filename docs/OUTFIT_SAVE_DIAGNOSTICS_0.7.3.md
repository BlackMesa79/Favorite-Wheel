# 服装预设保存失败调查与诊断补丁

2026-10-19，反馈者提供 `rhinsmdM.txt`（56,118 字节），插件版本 0.7.2、游戏 1.6.1170，系统区域 `nb-no`、界面回退为英文。

## 能确认的事实

- 原 `Capture` 在真正达到 100 套时提示 `outfitLimit`，但对 `Decode(Encode(updated))` 的任何失败也使用同一提示。这是误导提示的源码缺陷，不意味着用户真的有 100 套。
- 提供的日志中没有 `Outfit saved`、`Outfit validation`、`Invalid outfit record` 或 `Unable to save outfit presets`。因此没有成功创建服装预设的证据，也没有已记录的服装存档写入／读取失败。
- 两条 `Loaded 0 outfit presets` 在 22:13:52 和 22:15:42，早于 22:33–22:48 的保存窗口操作。不能把它们当成这些操作之后重新加载丢失数据的证据。
- 日志记录了一次战斗预设捕获；该次为明确空双手，不能据此验证所有服装物品数据都正常。
- 使用 nb-NO、de-DE、fr-FR、en-US 的 C 与 C++ 全局区域设置进行服装序列化回归，四组均通过。原模型已为读写流设置 classic locale，当前没有证据把故障归因于系统语言。

结合用户描述的提示，最可疑的是创建阶段的数据往返校验被拒绝；旧版不记录此分支的详细字段，无法确认具体哪件装备或字段。候选条件包括非正的强化值、超长自定义名／显示名、无效基础物品引用等，均仍是假设。

## 诊断补丁改动

- 将无效装备数据／记录校验失败的提示与真正的 100 套限制区分。
- 提取并共享原有物品数据校验；没有放宽条件、裁剪保存值、忽略装备或修改 FWO 1 格式。
- 失败时记录 `Outfit capture item rejected`、`Outfit capture rejected` 与 `diagnostic=outfit-capture-v1`，包括原因、预设数、物品顺序、基础引用、强化值及名称字节数。显示名预览有长度限制。
- 区分无衣物和超过 64 件的情况；真正达到 100 套仍使用原限制提示。
- 成功写入角色配套存档时记录 `Outfit co-save written` 的数量／字节数；失败也记录数量／字节数。
- 记录失败时仍不提交新预设，不覆盖旧预设。此补丁用于定位，不能宣称已修复反馈者的实际装备保存问题。

基于稳定 0.7.3，包含已验证的手柄修复，不包含战斗循环开发功能。补丁仅提供 DLL 与英文说明，未改玩家 INI、语言资源、自定义主题或旧发布包。新增提示在旧语言文件缺少键时使用内置英文回退；对应源码中的八种语言已补齐。

## 后续信息

请询问保存时所穿的护甲／服装，以及耐久、强化、属性或名称相关模组。尝试只穿一件普通、未附魔、未强化的原版护甲保存。若仍失败，安装诊断补丁后复现一次并提供本次完整日志，便可区分物品字段被拒绝与真正的存档写入问题。
