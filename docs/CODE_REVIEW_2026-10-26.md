## 已修复发现

### [P1] 数值排序可能永久停在加载状态

ChangeSorting 在旧目录已加载时先增加 directoryRevision，再将 inventoryLoading 设为 true 并请求新目录。如果旧刷新任务已占有队列标志，新请求会被合并；旧任务因 revision 过期不发布。此前输入泵只在 !inventoryLoaded 时补发，而这里 inventoryLoaded 仍为 true，且未必有新的背包变更触发另一轮刷新。

修复：用 DirectoryRequestNeeded 同时检查“尚未加载”和“仍在加载”，队列空闲才重试；已有目录重试用 refresh=true，保留分类／页面。测试模拟旧任务不发布而释放队列，确认下一次请求仍会发出，新目录完成后停止补发。

### [P2] 排序记录受进程地区数字格式影响

Ordering::Encode/Decode 未指定流 locale，可能继承其他插件修改的全局 C++ locale。FormID、强化位模式等较大整数会受数字分组规则影响，不同地区状态下读写可能不一致。

修复：读写均显式使用 std::locale::classic()，与换装记录的稳定数字格式策略一致。测试使用确定性的自定义千位分组 locale，覆盖大整数、中文／引号名称，验证输出字节一致并可读取经典格式记录。

### [P2] 发布包操作说明落后于已实现行为

package.ps1 仍描述双持法术“保留目标手、卸下另一手”，与当前目标手切换相反；也未介绍新排序／拖拽／会话轮盘记忆。

修复：更新未来生成包的说明，并在 README 添加明确标记为未发布的开发功能说明。保留历史版本条目，但指出已被当前法术行为替代。未执行打包脚本。

## 审查确认

- EndSortDrag 的玩家检查在 viewMutex 外执行，生命周期锁仍包围操作。排序自身的锁在 InsertItem 返回时释放，之后才刷新目录；短按移动在 viewMutex 作用域外调用。未再发现该松手链上的同锁递归。
- 拖拽释放在 InputGate 过滤前处理；取消、切换模式、目录刷新会清理拖拽状态。游戏线程目录快照不持久化原生指针；落位依赖当前目录与条目身份。
- 数值排序无效／缺失值统一排尾，同值名称排序；仅相关模式采集统计值。默认模式仍保留轻量路径。
- 新模式追加编号，旧自定义编号不变。零值换装数据保持原值，负数和非有限值仍拒绝；不改实际游戏装备数据。
- 轮盘记忆是显式默认关闭的会话选项，专用功能入口保持直达，限制形态不污染普通形态记忆。
- 语言部署只迁移已知旧默认文案，自定义文字保留；主 INI 不覆盖。

## 发布前边界与建议

1. 当前 xmake 版本仍是 0.8.0。正式打包前需先确定新版本号，避免把开发内容覆盖到既有 0.8.0 发布包；本轮没有变更既有包。
2. 使用新模式保存的排序记录不能由旧版完整读取，含 health=0 的换装也会被旧版拒绝；升级说明需明确这些降级限制。
3. 单元测试不能覆盖完整 SKSE 输入钩子、游戏线程和 Papyrus 卸装调度。用户已确认前一版实际操作正常，但本轮刷新补发修复仍建议简单游戏内回归：切换数值排序后正常出现条目、拖拽及跨页、保存后退出重载顺序。
4. 大背包的自定义排序比较器仍反复生成身份字符串，数字排序会计算所启用分类的全部实例数据。后续可按实际耗时优化排名缓存和采集范围；本轮未在用户游戏中测量，不能承诺零卡顿。
5. 非中英语言的新功能文案仍有英文回退；完善翻译、可重绑定排序键、法术更细分类属于体验改进，不作为这次稳定性修复的一部分。
6. PureDark Upscaler／Theo's Render Pipeline 的既有显示兼容性尚未得到证实修复，不能纳入本版已修复声明。

结论：已修复本轮审查确认的两处逻辑缺陷并同步发布说明。未发现额外可确认的发布阻断崩溃，但该结论不等同于无缺陷保证；可进入确定版本号和最终游戏回归的发布准备阶段。
