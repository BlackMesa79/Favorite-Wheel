# FavoriteWheel UI 渲染路线与美化设计

日期：2026-10-04。本文是当前工程的方案评估，不表示已经修改 UI、切换渲染器或实现新主题能力。当前 DLL 基线为 0.3.2；1.6.1170 已有用户实测反馈，1.5.97 外部反馈仍待返回。

2026-10-05 实施更新：用户选定继续 ImGui，先整体美化后再加功能。0.3.3 实现统一轮盘/面板风格、侧边详情、轻文字阴影、局部顶点渐变、短悬浮/翻页反馈及有界主题视觉参数，新增两个主题。采用原创程序几何，图片材质/纹理主题未接入；实时试穿仍暂缓。下文保留方案评估时的能力描述，当前实际字段见 [RESOURCES.md](RESOURCES.md)，验证状态见 [TESTING.md](TESTING.md)。

## 结论与优先级

建议保留 ImGui，优先重做视觉规范、布局细节与美术资源层。轮盘已经采用 ImDrawList 自定义绘制，可做精细的游戏 UI，不必受 ImGui 默认控件外观限制。当前观感主要由几何布局、文字处理、图标、材质与反馈设计决定，换渲染器本身不会自动改善美观度。

SWF 是可行的长期选项，适合把原生菜单生态、Flash 矢量美术与时间轴制作作为核心工作流的项目。若只是提升当前轮盘观感，迁移成本高于直接打磨现有绘制层。先保留当前输入、中文命名、HUD 层级和动作执行路径的实机成果。

实时试穿排在 UI 美化之后，设计见 [REALTIME_OUTFIT_PREVIEW.md](REALTIME_OUTFIT_PREVIEW.md)。无论 ImGui 还是 SWF，角色模型试穿与独立侧窗渲染均需要引擎侧工作；选择 SWF 不会自动获得玩家全身预览。

## 当前实现与真正可改的部分

- `src/Draw.cpp` 用路径、圆、线段和文字自绘扇区、标题、中心信息、设置与管理界面。改变 ImGuiStyle 只能影响使用相应样式的控件，无法整体重设计这些自绘内容。
- `include/WheelIcons.h` 是原创纯线条图标，统一 40×40 设计坐标和缩放线宽。用户已选择统一无填充，后续继续保持。
- 当前文字助手使用四方向黑色偏移描边再绘制正文。小字号可能显得厚重，可将描边强度、阴影和字重分工做成视觉规范。
- `src/WheelFonts.cpp` 已按实际输出像素字号烘焙、对齐并预热字形。继续保留 1440p 清晰度，不改成将低分辨率整张 UI 纹理拉大。
- 主题目前主要是配色与一个可选字体；尚无主题纹理、间距、图标资源替换或动画参数接口。布局还有固定比例/偏移。
- 当前开关有约 140ms/100ms 淡入淡出，渲染动画不延迟解暂停和动作执行。可继续增加局部反馈，但不能让动画改变操作时机。
- `src/Renderer.cpp` 已解决用户 Community Shaders 环境下的 HUD 合成层级。保持实际 UI framebuffer 绘制与状态恢复，不因美化回退到旧缓冲路径。

## ImGui 与 SWF 比较

| 维度 | 当前自绘 ImGui | Skyrim 原生 Scaleform / SWF |
| --- | --- | --- |
| 视觉能力 | 自定义几何、图片、字体、渐变和动画均可；复杂美术需自行组织 | 矢量、位图、文字、时间轴适合美术编辑；受游戏旧版 Scaleform 支持范围约束 |
| 美术制作 | 代码绘制、外部图片/矢量制作工具配合 | Flash/兼容工具中的可视化编辑更直接；需明确能被游戏读取的导出格式 |
| 菜单集成 | 已有自有 IMenu 生命周期与独立 D3D 绘制，输入/层级已实测 | 电影可由自有 IMenu 加载；融入原生菜单绘制栈，但层级、暂停标志、输入仍需设计 |
| 高清 | 按目标像素烘焙字体、几何抗锯齿及足够分辨率的图片 | 矢量缩放有优势；位图、字体嵌入、缓存和视口设置仍会影响清晰度 |
| 动画 | 自定义缓动/状态驱动，可精确控制；需实现资源与时间管理 | 时间轴/补间制作方便；C++ 与 ActionScript 状态同步必须可靠 |
| 中文与输入法 | 现有 NameEditor 与 Skyrim Text Bridge 已获用户确认 | 原生字体/翻译生态可参考；本轮盘的输入法、光标、选区和快捷键需要重新联调 |
| 主题 | 配色已有；拓展材质、字号角色、间距较直接 | 可暴露颜色/资源参数或替换 SWF；复杂布局主题仍需定义统一契约 |
| 性能 | 现有实现可持续测量优化，图片与局部效果可缓存 | 并非必然更快；矢量复杂度、滤镜、位图和脚本更新都可能增加开销 |
| 维护 | 一套 C++ 工程与现有离屏预览工具 | 增加电影源文件、脚本、导出工具链与 C++/GFx 桥，调试跨两层 |

SWF 的优势是资源制作与原生菜单集成，不是自动获得最高层级、最好性能或所有第三方 UI 兼容。SWF 图标库也不能直接任意使用：分类映射、资源定位、版本和作者授权仍需处理。此前搁置的 I4 社区图标适配保持搁置。

### 若以后迁移 SWF

保留 Favorites、Outfits、FaceLightClient、设置/本地化数据、动作队列与 epoch 检查，改写显示层和表现接口。需要新增：

1. 自有菜单加载电影与 GFx 桥，定义 C++ 向电影提供分类、槽位、状态和文字的值型数据协议。
2. ActionScript 到 C++ 的操作接口，避免脚本直接触及游戏对象；保持游戏线程/渲染线程边界。
3. 扇区命中、圆内光标、A/D 分类、翻页、设置、管理和命名界面；复测输入吞键与关闭后的物品使用。
4. 字体、翻译、中文输入、光标与选区；验证 Text Bridge，而不是假定两边都是 UI 就自动兼容。
5. 可复现的源文件、脚本与导出流程，分发 SWF 时同时保留可维护的美术源与许可证。

工程本地 CommonLib 的 BSScaleformManager::LoadMovie 和 GFx 类型已体现电影、字体、位图与渐变等支持，Flash 源资源也可见 AS2/CLIK。应以 Skyrim 可接受的旧版 Scaleform/AS2 工作流验证样片，不假定现代 Adobe Animate 的任意 SWF、AS3 或 HTML5 导出都能直接使用。是否接 SkyUI 是另一项选择，自有菜单不要求接入 SKSE Menu Framework。

## 其他可选路线

| 方案 | 擅长的场景 | 本工程的代价与判断 |
| --- | --- | --- |
| RmlUi | 类 HTML/CSS 的布局、样式、字体和保留式界面，适合更复杂的设置/管理页 | 不是完整浏览器；需接 D3D 渲染、输入、字体、纹理和生命周期。没有核实可直接复用的 Skyrim 集成，当前圆形轮盘收益有限 |
| Direct2D/DirectWrite、Skia 或自有 D3D 绘制 | 对矢量、文字或专用效果有更细控制 | 需要维护绘制、布局、命中、资源和跨渲染状态协调，容易重建现有 UI 基础设施；适合作为局部工具，不优先全面替换 |
| CEF、Ultralight 等嵌入网页方案 | 使用网页制作工具、复杂页面与丰富布局 | 要承担运行库、许可/分发、离屏纹理、输入和生命周期集成；对轻量 SKSE 轮盘代价偏大，不能当成普通网页直接嵌进去 |
| ImGui 加美术资源层 | 继续使用现有交互，提升材质、细节、排版与反馈 | 当前最直接；需要做好资源缓存、主题接口和分辨率策略，但不必迁移完整菜单 |

这些是可研究的技术路线，尚未接入或验证，不能按通用库的功能表宣称已经适配 Skyrim。

## 当前 ImGui 的美化路线

### 1. 先统一视觉规范

为标题、槽位名称、数量/装备状态、中心详情和操作提示建立明确字号、间距与对比度。图标保持一致的视觉尺寸、线宽和圆角，名字与数量不争抢同一行。小文字改为克制的阴影或必要处细描边，不把所有文字都做成厚黑边。

扇区基础色维持实心。悬浮用细强调弧线、边缘亮度和轻微色差表达，已装备/不可用状态用紧凑标记与文字表达，不能仅靠颜色。保留 `< 当前分类 >`，不给标题重新堆满分类标签。

### 2. 为局部加入美术资源

可增加克制的刻纹外环、金属边缘、分隔装饰或细颗粒材质，轮盘内容区域保持干净。设置与管理面板可用九宫格纹理维持边角比例，图标仍保留原创纯线条。整体可以偏上古卷轴的雕刻/羊皮纸风格，也可以选择简洁深色风格，先用一个统一方向做样稿。

ImGui 的 AddImage 接收纹理，不直接解析 SVG。矢量资源可以转换为绘制几何，或按目标尺寸预栅格化为纹理；不要每帧解析 SVG、读文件或重建纹理。图片与图集在加载/切主题时处理，稳定帧复用。分辨率、缩放和显存预算应显式设计。

### 3. 用局部效果和短动画强化反馈

扇区可通过几何网格/纹理实现局部渐变、细阴影与少量高光；这些不需要采样并模糊整个游戏背景。保留已稳定的可调遮罩，不恢复此前造成严重掉帧的背景模糊。

悬浮强调、分类标题切换、翻页与开关可以有短缓动。动画只消费已准备好的值快照，状态变化时启动，不为动画每帧查询库存、调用模型重建或重新提交动作。支持关动画；使用/换装仍遵循现有执行时机。

### 4. 重新整理紧凑布局

轮盘中心优先显示当前名称与关键状态，较长说明用旁边小详情卡承载。基础快捷键保持一行紧凑提示，复杂操作只在相关页面显示。靠左轮盘的右侧可预留未来装备预览区域，眼下不要求填满，也不改成占满屏幕的大面板。

按安全边距限制卡片与提示位置，避免调节 X/Y/大小后越界。测试长中文、长英文、空分类、十个槽位以及缩放极限，不以一张默认布局截图作为唯一依据。

### 5. 扩展主题，但保留清晰的边界

拟新增主题字段：字体角色/尺寸比例、边框与间距、图标比例、外环/面板纹理、局部高光强度、动画时长。资源采用模组内相对路径，缺失项有默认回退，旧主题继续能读。主题配置负责视觉，个人位置/快捷键等留在用户设置，本地化继续独立。

这套字段尚未实现。字体分发需有许可证；CJK 字形覆盖及回退需要明确实现，不能暗示现有字体加载已具备完整复杂文字排版能力。用户本地语言、主题与 INI 在自动部署时继续保留。

## 建议实施顺序与验证

1. 用现有 WheelPreview 制作同数据的视觉样稿，先确定轮盘、详情卡、设置页统一风格；此阶段无需动游戏行为。
2. 实现布局/字体角色与扇区状态规范，保留已确认的 1440p 清晰度、纯线条图标、指针约束和 HUD 层级。
3. 加资源缓存与主题可选材质，再增加可关闭的局部动画。每次改动只验证涉及的行为。
4. 输出 1280×720、2560×1440、3840×2160 的离屏预览；检查极端缩放、长翻译、命名选区和空页。离屏结果不替代游戏测试。
5. 实机检查 CS 环境合成、中文输入、失焦/关闭与长时间切页，对比相同场景的帧时间和资源使用；1.5.97 与 1.6.1170 分别验证涉及的改动。

当前任务只形成设计文档，没有新增可部署构建，未运行 UI 行为或性能测试。
