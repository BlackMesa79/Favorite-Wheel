# 轮盘减速与全部背包模式：可行性评估

日期：2026-10-07（Asia/Hong_Kong）。历史评估基线0.4.0；评估当时未改变代码或部署。后续用户授权全部背包开关，0.4.1已实现，见[INVENTORY_MODE.md](INVENTORY_MODE.md)。减速模式仍仅评估，未实现。

## 结论

两项均可保留现有ImGui/D3D11绘制，独立实现，不引入Wheeler或Fallout 4模组依赖。建议作为两个独立设置：时间行为（暂停/减速/正常速度）与物品来源（仅收藏/全部背包）。原有默认保持暂停+仅收藏，用户可自行组合。

| 需求 | 可行性 | 主要成本 |
| --- | --- | --- |
| 打开时减速 | 可行，初步效果较容易 | 完整版为中等偏高：时间倍率恢复、其他减速来源、菜单生命周期、实时状态和异常关闭 |
| 全部背包分类轮盘 | 可行，分类与分页可复用 | 中等：堆叠与特殊实例、执行校验、信息/字体开销、不可直接使用物品的交互 |

建议先扩展物品来源与实例解析，再单独增加时间模式，最后测试两项组合。这样减速时的物品变化可复用较完整的库存解析，而不是同时改数据源与菜单生命周期。

## 一、打开轮盘时减速

### 当前机制和可复用部分

PauseMenu构造时设置kPausesGame/kDisablePauseMenu/kUsesMenuContext；真正导致游戏暂停的是菜单标志，不是ImGui绘制。可根据选定时间模式创建对应菜单状态，减速模式不设置kPausesGame，继续使用当前输入捕获与菜单上下文。

CommonLib已有BSTimer::QGlobalTimeMultiplier、QGlobalTimeMultiplierTarget和SetGlobalTimeMultiplier接口。可以尝试给轮盘会话施加相对开盘前倍率的减速系数，例如20%：正常速度1.0变0.2，开盘前若已减速则不能直接写绝对0.2导致反而加速。原生当前/目标倍率、渐变以及SlowTime魔法效果的叠加语义需原型实测，不能把“乘一个系数”视为所有时间来源的完整仲裁。

当前折扇动画、ImGui DeltaTime与设置页手柄光标使用steady_clock/真实时间，因此无需让UI响应跟着游戏减速。不能把UI动画计时改为游戏delta。

### 建议体验

- 提供暂停、减速、正常速度三个独立模式，减速比例可调；第一轮建议测试10%、20%、30%，默认是否改为减速待体验后确定。
- 普通收藏及功能轮盘使用所选模式；设置、预设命名与删除/覆盖确认等长交互建议临时暂停。通过独立暂停子菜单或正确的UI暂停计数机制实现，不能仅在已打开菜单中随意改标志，导致引擎计数不匹配。
- 打开后捕获玩家控制，阻止攻击、移动、施法与视角输入穿透；世界继续运行，玩家仍可能受伤或死亡，减速不等于无敌。
- 选择操作后先可靠结束菜单及本轮减速，再提交当前动作；视觉收拢不延迟速度恢复、装备或消耗品使用。

### 完整实现必须处理

1. 时间会话状态：记录取得的当前/目标倍率及本轮施加状态，正常关闭和强制关闭统一释放。不能每次关闭都写1.0，否则会覆盖其他来源。
2. 同时修改时间的插件/效果：没有发现可直接复用的跨插件时间所有权协议。朴素快照恢复会丢掉开盘期间的外部变化，逐帧强写会与其他插件争抢。需观察当前/目标倍率并设计外部变更时释放或重新评估的策略；行为相同的外部写入仍可能无法识别。不能承诺和所有时间模组兼容。
3. 正常退出、失焦、死亡、加载、主菜单、菜单被强制隐藏及渲染失败：覆盖现有Cancel/ProcessMessage/SetGameActive路径，并确保恢复请求有不依赖暂停后PlayerUpdate继续执行的处理入口，避免卡在减速状态。
4. 实时数据：轮盘打开后脚本可能修改背包、装备、玩家属性，面光目标可能离开或revision变化。选择时重新核验；使用中的目标保持开盘前锁定，不能后台刷新后悄悄换成另一个准星NPC。
5. 原有面光接口线程、session/revision校验保持；需要刷新时仍走认可的PlayerUpdate线程，不从Present或输入线程调用API。stale请求不盲目重试。
6. 全局倍率对动画、音频、Havok、SMP及菜单运行规则的实际效果需联测；第三方按真实时间运行的部分可能不以同样比例减速。UAPNG/EAS仍走已有EquipObject使用路径。
7. 五个运行时地址库需额外检查BSTimer单例523657/410196、倍率511882/388442、目标511883/388443、setter66988/68245。现有15个关键地址测试未覆盖这些新调用，不能沿用旧结果宣称验证完成。

不建议用控制台SGTM命令作为正式接口，也不建议为UI减速临时给玩家添加慢时间法术；原生时间接口更直接，但仍需处理上述状态恢复与叠加。

## 二、显示全部背包物品

### 当前机制和必要变化

CollectFavorites已经读取完整GetInventory结果，再要求entry->IsFavorited且实例有ExtraHotkey。因此分类、排序、十格分页、详情卡片、图标、导航可以复用。

但不能只删除IsFavorited判断：后续仍跳过没有ExtraHotkey或没有extraLists的物品，而普通库存堆叠恰好可能没有独立实例数据。UseFavorite和BindFavoriteQuickSlot执行前也重新调用CollectFavorites，若仅改变显示端，非收藏物品会显示却无法使用。

建议统一库存模型和实例解析，显示来源控制过滤，执行端按实际拥有情况与实例身份校验。实例extra=null可代表未单独跟踪的普通堆叠，但这不是对强化/附魔实例的回退许可：特殊实例失配应提示变化，不能换用同FormID的其他装备。

### 建议首版规则

- 所有实际持有的武器、弹药、护甲/服装/首饰、药水、食物、卷轴、火把均无需收藏即可显示并使用；继续采用现有分类和分页。
- 同种普通堆叠合并数量，强化、附魔、自定义名字与穿戴实例按差异区分；防止带实例计数与普通剩余数量重复计算或漏算。
- 全部背包严格指背包。魔法分类建议首版仍为收藏法术/龙吼；“全部已学法术/龙吼”作为另一项范围，不能当作GetInventory直接提供。若实现，排除能力/疾病/被动效果等不可主动装备内容。
- 杂物、书籍、钥匙、原料与毒药可在其他分类展示，但明确不可直接使用状态。显示全部不自动提供读书、吃原料、涂毒、丢弃或容器转移；这些需要逐类实现原版交互。
- 收藏标记可作为排序/显示依据，建议已装备、收藏项靠前，其后名称排序，避免常用物品被大量库存淹没。大量药水可以后续增加恢复/增益等子筛选，不要第一版依据名字猜类型。
- 全库存物品不隐式全部加入原版收藏。首版1–8只绑定已收藏项，非收藏项给出提示；若之后允许直接绑定非收藏，必须明确这是“加入收藏并绑定”，由游戏线程使用原生收藏机制创建数据后再分配槽。

### 性能与实时一致性

背包有100件同种箭通常是一个条目，100件不同附魔/强化装备可能是100个实例；负担来自条目/实例/属性计算和字形数量，而不是物品总数量。

当前开盘为所有收藏计算完整属性与效果，拼接全部名字/详情字形，并在首帧为多个字号重建字体图集。扩展到数百或上千实例若原样照搬，可能增加开盘卡顿、内存和字体纹理开销。渲染每页仍只有十项，绘制负担不会简单随库存总数成倍增长。

建议先采集轻量身份/名称/数量/标记快照，详情按可见页面或稳定悬停请求并缓存；实际读取仍在游戏线程，渲染只拿值。首次出现字形仍需准备，不能从异步线程直接遍历游戏库存或重建共享ImGui字体。是否做按分类字形预热需测量，避免分页后反复字体重建。

暂停模式可在一次开盘期间保持目录快照，执行前重验；减速模式应增加库存变更dirty标记、游戏线程适度合并刷新，平稳更新数量和装备状态。不要每帧GetInventory/计算全部属性。刷新时优先保留当前选中实例与分类，条目消失时清除选择，不能让同一扇区换成别的物品后误用。

## 验证与实施边界

两项不要求SWF、不要求SKSE Menu Framework、不更换现有原创图标。库存扩展先确认零extra实例、负/剩余数量、同FormID特殊装备、不收藏消耗品动画、原生快捷槽和大量物品开盘成本。减速另测时间外部变更、异常退出与嵌套暂停、输入吞放、面光stale请求、真实时间UI动画。

本次没有测量新增功能性能或实现新时间控制，不提供未经原型验证的开发工期/帧率保证。0.4.0部署和包保持不变。
