# 0.4.3 代码复核

2026-10-07：用户反馈0.4.2游戏内测试未发现问题。本轮针对减速/暂停生命周期、实时库存目录、悬停详情与动作队列检查边界路径，修复以下问题。这里记录的是代码路径风险，不表示用户已经遇到这些故障。

## 修复

1. **时间同步与关闭可以交错。** `SyncWheelTime`原先在读取`view.open`后单独更新倍率和请求暂停；另一个入口可能在这期间执行`Cancel`，随后旧同步仍请求暂停。现在开盘请求/实际开盘、时间同步、取消、原生轮盘与暂停菜单消息、游戏加载状态切换共用`lifecycleMutex`。取消完成后，后续同步会看到已关闭状态，不会重新取得减速或请求暂停。`PumpOpen`的状态核对也在同一保护内，避免核对后被取消却继续打开。
2. **C++异常可能留下排队标志。** 目录、详情和动作任务原先只在末尾手动清除`*TaskQueued`；读取、分配或任务提交抛出异常后，该类后续请求可能一直被拒绝。`RunQueuedTask`在退出/展开栈时释放槽位，`ScheduleQueuedTask`覆盖提交失败；延迟开盘也使用退出保护。错误记录日志、取消对应轮盘并释放自己的时间会话；换装任务请求停止后续操作。错误清理再次核对存档epoch/开盘serial，旧任务不能关闭新轮盘，旧存档不能取消新存档的换装。已完成的装备操作不回滚，且本保护不捕获原生访问违例/SEH。
3. **缓存命中绕过悬停计时。** 详情已缓存时原先提前返回，不记录新悬停项；从A移到缓存B再立即移回A，可能跳过80ms稳定悬停门槛。现在先更新悬停身份，再判断缓存有效期；重新开盘也按serial重置计时。详情再次读取成功时清除之前的“物品已变化”提示。

## 锁顺序与性能

生命周期锁在进入上述操作时取得；`viewMutex`、`openMutex`、`pauseMutex`和时间控制锁的持有范围仍局部化。现有调用点进入生命周期操作前已退出视图/动作/开盘锁；`TakeAction`检查时间状态的同时不进入生命周期锁。设置、面光快照的内部锁也在返回后释放。递归锁允许同步检测到冲突时调用`Cancel`，并允许原生消息路径进入同步。没有在渲染线程添加库存扫描，也没有新建每帧任务；真实目录仍按事件合并刷新，页面最多复制10项。

这些是本项目可见代码的锁顺序检查；单元测试不能证明引擎和第三方插件的全部调度。快速开关、设置切换、失焦/读档和第三方菜单仍需要实机回归。

## 验证

Release编译通过；TimeTests、SettingsTests、InventoryTests、WheelLogicTests和OutfitTests通过。新增TimeTests故障注入检查延后执行、读取异常、提交分配异常、未知C++异常、提前返回、错误报告展开栈、后续重试，以及错误清理保留已有减速基准。RuntimeLayoutTests通过五版本模拟布局、地址库格式1/2/5与实际0.4.3 DLL元数据；没有新增地址/hook，未重复0.4.2的五份真实地址库检查。真实菜单消息调度和新悬停路径由代码复核及用户复测覆盖，不将纯逻辑测试当作游戏内并发验证。无绘制变化，不重复离屏预览。

## 保留的兼容限制

没有跨插件时间仲裁协议：其他模组写入相同倍率，或变化恰好符合当前原生渐变区间时，无法可靠识别所有权改变。可识别的外部改变仍让出控制并关闭轮盘，关闭时不把倍率硬写为1.0。0.4.2的用户正面反馈不等于全部战斗/慢时间效果/物理与动画模组组合已验证；0.4.3修复仍需复测，1.6.640与1.7系列也仍待实机反馈。
