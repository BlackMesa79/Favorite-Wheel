# 0.4.9 轮盘输入隔离

验收补充（2026-10-08）：用户确认修复测试“一切正常”，授权合并到0.5.0正式版。以下保留调查时的实现依据与复测计划，不表示发布仍等待此修复验收。

2026-10-08：用户反馈0.4.3–0.4.8合并测试基本正常，但轮盘内按RB切分类会打开Horde管理页面。继续以0.4.9测试构建处理，不提前发布0.5.0。

## 现场证据与判断

本机安装Horde 3.0.0。只读检查其settings.json：useKeybinds=false，列出的入口是键盘扫描码，没有单独RB绑定。Horde日志明确记录“controller access through the Horde lesser power”；RB通常是游戏声音槽施放键。因此这很可能是声音槽能力被误发动，并非Horde直接抢占分类快捷键。没有读取玩家当前声音槽或观察实际施放回调，不能把这个具体触发路径视作已经实机证明。

FavoriteWheel旧InputHook对InputGate::Suppress将value与heldDownSecs都置零，但仍把原始ID/userEvent的ButtonEvent派发给引擎和后续插件。这不是真正移除事件；它虽然不满足原生IsDown/IsUp，仍可被按ID、IsPressed反向条件或零值松键分支处理。代码层面明确存在该隔离缺口。

现场Horde先安装派发钩子，FavoriteWheel后安装并串接之前的函数。修复覆盖本轮盘之后的事件派发路径；不能控制在外层钩子抢先读取事件或独立轮询控制器的任意插件。没有修改Horde文件或其设置，也没有复制其实现。

## 实现与review

- InputGate策略不变：Pass原样转发；Resume为已按住方向恢复一次新按下；Release为游戏已经看到的动作发送一次必要松键；Suppress才从派发链移除。真实补松键可能结束开盘前已经开始的蓄力/声音动作，这是必要的既有语义，不伪造已吞按钮的松键。
- InputDispatchChain是临时的引擎事件链视图。按原顺序访问节点，只修改前一个保留节点的next；不释放/复制事件，不改设备物理状态，不改引擎queueHead/queueTail。局部头指针不会覆盖引擎原头。
- 所有下游派发完成后RAII恢复被改动的next，异常展开也恢复。记录链指针之前先完成分配；未过滤的空闲批次和全部被过滤的批次都不需要保存节点链接。成本随当前输入批次的链接缺口增长，与背包大小无关。
- 按钮吞键状态仍以真实输入更新，跨关闭一直保护到物理松开；不能只过滤当次按下、随后漏出held/up。
- 移动方向、摇杆、原生快捷槽、开盘/设置/命名流程沿用原策略。Text Bridge热键/修饰键和命名字符保留；内层Text Bridge可在本次同步派发中插入字符，外层已插入字符也不会被按钮过滤丢弃。被其他钩子永久重接或释放的节点不属于该临时事件链协议。
- 增加Controller category input日志：记录LB/RB原始码、SKSE码、userEvent、removed/release/pass。每次按下记录，不逐帧记录held。
- 不新增地址、原生钩子、设置字段、翻译键或存档格式；无需重新保存预设或重置INI。
